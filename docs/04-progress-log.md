## 🔴 آخر نقطة توقف (Where we stopped)

**المرحلة:** اكتملت **صفحة تسجيل الدخول** مطابقة للريفيرنس، والسيرفر شغّال.

**الحالة بالضبط:**

- `eduspace-web/` مشروع Vite + React + TypeScript فيه **صفحة لوجين كاملة وعاملة**.
- **مطابقة لصورة الريفيرنس** في التقسيم (52.8%/47.2%) ونسبة الكارت للصورة (0.671) ومواضع عناصر الفورم (فرق ≤ 2px).
- **الشعار الرسمي** لـ `edulink` مركَّب في اللوحة والكارت والأيقونة المفضلة، بنسختين للفاتح والغامق.
- **روح المشروع:** كل الحقول والأزرار والصناديق **بيضاوية**، والكارت باستدارة كبيرة، ومربع الاختيار دائري.
- **الصفحة متجاوبة فعليًا** (الزووم يعمل طبيعيًا)، و**لا تمرير** من 1366×768 وحتى 1920×1080 وعلى الجوال 390×844 عند زووم 100%.
- **حقول الإدخال 16px أو أكثر** فلا يعمل iOS زووم تلقائي عند الكتابة.
- **جاهزة للنشر على Vercel** — الإعدادات والخطوط المحلية وتحسينات الأداء مكتملة (`docs/06-deployment.md`).
- `npm run build` و `npm run lint` ناجحان (0 أخطاء، 0 تحذيرات).
- **المصادقة غير موصولة بخادم** — `services/auth.ts` يرمي خطأ مقصود، والواجهة تعرض رسالة واضحة بدل نجاح وهمي.
- الـ backend (ASP.NET Core) وقاعدة بيانات SQL Server **لم يبدأ**.
- مجلد `tmp/` فيه سكربتات القياس (`measure-ref.ps1`, `probe-ref.ps1`, `palette.ps1`, `zoom-logo.ps1`, `crop.ps1`) — أدوات عمل مؤقتة.

**الخطوة التالية المقترحة (تنتظر قرار صاحب المشروع):**

1. **مخطط قاعدة بيانات SQL Server الكامل (ERD)** — الأدوار والصلاحيات، الجدول الأسبوعي المتكرر والحصص التعويضية، سجلات الحضور، عدّادات ساعات المدرسين.
2. أو البدء في **لوحة تحكم المشرف** (إضافة المدرسين والطلاب) قبل الـ ERD.

⚠️ **ملاحظة عن السيرفر:** `npm run dev` شغّال في الخلفية على **المنفذ 5174** (المنفذ 5173 كان مشغولًا من جلسة سابقة). لو المنفذ اتغيّر تاني، اقرأ الرسالة في الطرفية.

### الخطوة 8 — 2026-09-11 — صفحة واحدة في كل الشاشات + الصورة بدون قص
- **طلب صاحب المشروع:** الأبعاد كانت كبيرة شبه «زوم»، وظهور تمرير في صفحة اللوجين. المطلوب: **صفحة واحدة في كل شاشات الويب بدون أي تمرير**، و**الصورة المجاورة للكارت تُعمل «زووم أوت» بدون قص وبدون تغيير أبعادها**.
- **الحل — مقياس موحّد `--u`:**
  - أُضيف متغيّر `--u` في `tokens.css`: قيمته `1px` عند ارتفاع شاشة 1024px وأكثر (مقاس الريفيرنس)، ويتقلّص بنسبة ارتفاع الشاشة على الشاشات الأقصر (`calc(var(--screen-h) / 1024)`).
  - كل مقاسات الصفحة (الخطوط، الحشو، المسافات، الأحجام، الاستدارات، الأيقونات) صارت `calc(N * var(--u))` — أي زووم أوت متناسب للصفحة كلها.
  - على الشاشات الضيقة (≤980px) يُراعى العرض أيضًا: `min(..., calc(100vw / 600))`.
- **الصفحة بلا تمرير:** `height: 100dvh; overflow: hidden` مع توزيع يضمن أن الكارت يدخل كاملًا.
- **الصورة بدون قص:** `object-fit: contain` بدل `cover`، وعرض اللوحة = `min(52.8%, ارتفاع الشاشة × 0.66667)` أي بنسبة الصورة نفسها (2:3) فتملأ اللوحة تمامًا بلا فراغات جانبية. وأُضيفت نسخة مموّهة خلف الصورة لتغطية أي فراغ دوني.
- **التحقق:** اختُبرت 8 مقاسات — `1920×1080`, `1536×864`, `1440×900`, `1366×768`, `1280×720`, `1024×600`, `2560×1080`, `390×844` — والنتيجة: **`vScroll = 0` و `hScroll = 0` في كلها**، والكارت داخل الشاشة دائمًا، ونسبة عرض اللوحة = 0.667 = نسبة الصورة بالضبط.
- لقطات محدَّثة في `docs/screenshots/`.

### الخطوة 9 — 2026-09-11 — إرجاع النِسَب الأصلية ومطابقة 100%
- **طلب صاحب المشروع:** مطابقة صورة الريفيرنس **100% بكل تفصيله وكل النِسَب**، ومنها **النسبة بين الكارت والصورة** المجاورة له.
- **التشخيص:** التعديل في الخطوة 8 كان يجعل عرض اللوحة = نسبة الصورة (37.5% على شاشات 16:9)، فاختلّت نسبة الكارت إلى الصورة.
- **الحل:** `--u` لم يعد معتمدًا على الارتفاع وحده، بل **أصغر القيدين**:
  ```css
  --u: min(calc(100vw / 1536), calc(100vh / 872));
  ```
  أي أن التصميم يُكبَّر/يُصغَّر **ككتلة واحدة** بنسبة 3:2، فتبقى كل النِسَب صحيحة، والباقي يذهب حشوًا في لوحة الفورم.
- أرجع عرض اللوحة إلى **52.8%** والصورة إلى **`object-fit: cover`** مطابقةً للريفيرنس (وأُزيلت طبقة الـ backdrop التي لم تعد لازمة).
- **التحقق على 10 مقاسات:** عرض اللوحة = **52.8% في كلها**، ونسبة الكارت/الصورة = **0.664–0.671** (الريفيرنس 0.671)، و**تمرير = 0 في كلها**.
- **المطابقة على مقاس الريفيرنس (1536×1024):** اللوحة 811px، الكارت 544×768 عند y=128، حقل البريد y=395، زر الدخول y=624، زر Google y=738 — **كلها بفرق ≤ 2px** عن الريفيرنس.
- **قيد مسجَّل:** صورة الريفيرنس رندر مختلف عن الصورة النظيفة؛ المقارنة الرقمية (بحث عن أفضل مقياس وإزاحة) تُظهر فرقًا ≈ 16% حتى عند أفضل تطابق، فالتأطير الداخلي لا يمكن أن يكون متطابقًا بكسل-بكسل بدون ملف الصورة الأصلي.

### الخطوة 11 — 2026-09-11 — التجهيز للنشر على Vercel بأقصى سرعة
- **طلب صاحب المشروع:** تجهيز المشروع للنشر على Vercel بأقصى سرعة.
- **إعدادات النشر:** أُضيف `eduspace-web/vercel.json` (framework: vite، `npm ci`، `dist`، `cleanUrls`، إعادة توجيه SPA، كاش immutable لـ `/assets` و`/fonts`، وترويسات أمان).
- **تحسينات أداء حقيقية (مع أرقام):**
  1. **الخطوط محليًا:** كانت من Google Fonts (طلب خارجي + DNS/TLS + CSS حاجب للرسم). الآن **3 ملفات متغيّرة** في `public/fonts/` (Cairo arabic+latin، Inter latin) تغطّي الأوزان 400–800، ويُحمَّل **ملف واحد فقط** حسب اللغة.
  2. **نسخة الاسم في الشعار:** كانت نسختا الفاتح والغامق تُنزَّلان معًا (`<img>` يُحمَّل ولو كان `display:none`) — صارت خلفية CSS فلا يُنزَّل إلا ملف الثيم الفعّال (وفّر ~50KB).
  3. **صورة اللوحة:** كانت تُنزَّل على الجوال رغم إخفاء اللوحة — صارت خلفية CSS داخل لوحة مخفية (وفّر 125KB على الجوال).
  4. **LCP:** صورة اللوحة تُطلَب مسبقًا (`preload` + `fetchpriority=high`) من `<head>` على الشاشات >980px فقط، فتبدأ بالتنزيل بالتوازي مع الـ JS بدل الانتظار حتى يرسم React.
  5. **منع الوميض:** سكربت مضمّن يطبّق المظهر **واللغة والاتجاه** قبل أول رسم (كان الاتجاه ينقلب بعد التحميل).
  6. **CLS:** `aspect-ratio` لكل صور الشعار.
- **التحقق على نسخة الإنتاج (`vite preview`):** الخطوط تُحمَّل محليًا، ونمط الثيم يجلب نسخته فقط من الشعار، والجوال لا يجلب صورة اللوحة إطلاقًا.
- **التوثيق:** أُضيف `docs/06-deployment.md` (طريقتا النشر + جدول الترويسات + جدول الأداء) و`README.md` في الجذر، و`.gitignore` في الجذر.
- ⚠️ **ملاحظة مهمة مسجّلة:** لو استُورد المستودع في Vercel يجب ضبط **Root Directory = `eduspace-web`**، وإلا يفشل البناء.
- **ملاحظة:** ترويسة `Permissions-Policy` تسمح بالكاميرا والمايك من نفس النطاق عن قصد — لأن الجلسات المباشرة (LiveKit) ستحتاجها.

- **المرجع المستخدم:** وُجد مشروع **`NileTechno`** على الجهاز (Clean Architecture: Domain/Application/Infrastructure/API مع MediatR + FluentValidation + AutoMapper وfeature folders) — اعتُمد كمعيار، مع معيار `apps/ + packages/` للـ monorepo.
- **نقل الجذر:** جذر المستودع انتقل من `eduspace-web/` إلى `Eduspace/` (نُقل مجلد `.git` نفسه)، فدخل التوثيق داخل المستودع أخيرًا ✓
- **الهيكل الجديد:** `apps/web` (الواجهة) · `apps/api` (الباك اند) · `packages/shared-types` · `database/` · `docs/`.
- **الواجهة:** أُعيد ترتيبها إلى `app/` (راوتر + مسارات) · `components/` (مشترك) · `features/auth` · `features/dashboard` · `layouts/` · `lib/` · `locales/` · `pages/` · `styles/` · `theme/`.
  1. **صفحة = مجلد + مسار**: Login `/login`، Home `/home`، Schedule `/schedule`، Sessions، Students، Reports، Messages، Settings (+ ComingSoonPage).
  2. **الترجمة لكل صفحة (namespaces):** `locales/{ar,en}/{common,login,dashboard}.json` والاستخدام `t('login:form.submit')`.
  3. **المسارات في ملف واحد** `app/router/paths.ts` — لا مسار مكتوب نصًّا في أي مكوّن.
  4. **حزمة `@eduspace/shared-types`** فيها أنواع عقد الـ API المشتركة، والواجهة تستوردها عبر npm workspaces.
- **التحقق:** `lint` و`build` نظيفان، **والدخول مُختبَر فعليًا من المتصفح بعد الهيكلة**: `/login` → تسجيل الدخول → التحويل التلقائي إلى `/home` مع الاسم والدور الحقيقيين ✓
- **⚠️ لم يُنفَّذ:** تقسيم الباك اند إلى مشاريع Clean Architecture الأربعة (`apps/api` حاليًا مشروع واحد عامل ومُختبَر). التفاصيل والمعيار في `docs/09-structure.md`.
- **ملاحظة:** مجلد `eduspace-web` القديم فَضَل فاضيًا (مقفول من عملية) — لا أثر له على Git.

## ❓ نقاط مفتوحة

### تنتظر قرارًا من صاحب المشروع
1. تأكيد **ASP.NET Core** كباك إند نهائي.
2. تأكيد **LiveKit** كمحرّك الفيديو.
3. وجهة **تخزين ملفات المدرس**: مساحة ملفات أم داخل SQL Server.
4. تفاصيل **صلاحيات كل دور** (قال إنه سيتكلم عنها لاحقًا).
5. نظام **الإشعارات** (إيميل / تذكير قبل الحصة / Push).
6. التعامل مع **المناطق الزمنية** للحصص.
7. **اللوجو الرسمي** (SVG) وصور الأفاتار الحقيقية.

### نقاط تقنية داخل صفحة اللوجين
1. **زرّا «نسيت كلمة المرور» و«تواصل مع مؤسستك»** لا وظيفة لهما بعد (بلا معالِج) — ينتظران مساراتهما.
2. **تسجيل الدخول** يعرض رسالة «غير متصل» — ينتظر بناء الـ API.
3. **حقل الدخول** عنوانه «البريد الإلكتروني» كما في الريفيرنس، لكن التحقق يقبل **رقم الهاتف** أيضًا (المتطلبات تسمح بالاثنين) — يحتاج قرارًا في التسمية النهائية.
4. **تعدد اللغات**: حاليًا الترجمة داخل JSON؛ لو المنصة ستُباع لمؤسسات قد تحتاج تخصيص بعض النصوص لكل مؤسسة لاحقًا.
5. **كلمة المرور** إلزامية بحد أدنى 8 أحرف — يحتاج تأكيدًا من سياسة المصادقة الفعلية.
