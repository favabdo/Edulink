# Eduspace API — الباك اند

ASP.NET Core Web API (.NET 10) يخدم تطبيق الويب في `../` (مشروع Vite).

> **قاعدة البيانات:** المصدر الوحيد للمخطط هو **`database/schema.sql`** في جذر المستودع (قسم PostgreSQL في الأعلى، وقسم SQL Server في آخره). **لا تُستخدم EF Migrations إطلاقًا** — الكيانات تقرأ وتكتب فقط.

---

## التشغيل محليًا

```bash
cd api
dotnet run --launch-profile http
```

يعمل على `http://localhost:5279`، وتطبيق الويب يمرّر إليه `/api` تلقائيًا عبر بروكسي Vite (في `vite.config.ts`) فلا نحتاج CORS في التطوير.

في التطوير المحلي يُستخدم **SQLite** (`eduspace.dev.db`) ويُنشئ التطبيق جداوله من نموذج الكيانات تلقائيًا. الملف غير مُتتبَّع بـ Git.

### إنشاء أول حساب (الأونر)

لا يوجد تسجيل ذاتي. لإنشاء أول حساب:

```bash
curl -X POST http://localhost:5279/api/setup/owner \
  -H "Content-Type: application/json" \
  -d '{"name":"مالك المنصة","email":"owner@edulink.test","password":"Owner@12345"}'
```

⚠️ **على Windows/Git Bash لا تُرسل العربية في سطر الأوامر** — `curl` يحوِّل الوسائط إلى cp1252 فتُخزَّن `Name` كلها `?` (مقيس: `-d '{"name":"طالب ألفا"}'` أنتجت «???? ????» في القاعدة، بينما نفس النص من ملف وصل سليمًا). الصيغة الآمنة على النظامين — والجسم من ملف UTF-8:

```bash
printf '{"name":"مالك المنصة","email":"owner@edulink.test","password":"Owner@12345"}' > owner.json
curl -X POST http://localhost:5279/api/setup/owner \
  -H "Content-Type: application/json" --data-binary @owner.json
```

`deploy/run.sh` يستخدم هذه الصيغة نفسها في خطوة المالك.

هذا المسار **يُعطِّل نفسه تلقائيًا**: يعمل فقط إذا كانت قاعدة البيانات بلا أي مستخدم، وبعدها يرجّع `409`.

## التحويل إلى Supabase (PostgreSQL)

### 1) أنشئ الجداول
**Supabase → SQL Editor → New query**، والصق محتوى **`database/schema.sql`** كاملًا ثم **Run**.
الملف قابل لإعادة التشغيل بأمان.

### 2) هات سلسلة الاتصال
**Supabase → Project Settings → Database → Connection string → URI**:

```
postgresql://postgres.<ref>:<PASSWORD>@aws-0-<region>.pooler.supabase.com:6543/postgres
```

### 3) اضبط الإعدادات
أسهل طريقة للتطوير المحلي: ملف **`apps/api/appsettings.Development.json`** (مستثنى من Git):

```json
{
  "Database": { "Provider": "Postgres", "EnsureCreated": false },
  "ConnectionStrings": {
    "Postgres": "Host=aws-0-<region>.pooler.supabase.com;Port=6543;Database=postgres;Username=postgres.<ref>;Password=<PASSWORD>;SSL Mode=Require;Trust Server Certificate=true"
  }
}
```

⚠️ **`EnsureCreated=false` مهم:** التطبيق لا ينشئ ولا يعدّل أي جدول — المخطط من `database/schema.sql` فقط.

### 4) تأكّد أن الـ API يقرأ من Supabase فعلًا

```bash
curl http://localhost:5279/api/health/db
```

يجب أن يظهر `"provider":"Postgres"` و`"canConnect":true` مع `usersCount` بالعدد الحقيقي،
وفي بيئة التطوير `serverVersion` بنسخة PostgreSQL — إثبات مباشر أن القراءة من القاعدة.

### 5) اختبار كامل يثبت أن الـ API يقرأ من القاعدة

1. أضف صفًّا **من SQL Editor مباشرة** (لا من الـ API):
   ```sql
   INSERT INTO "Edu_Users" (name, email, password, role, states, access)
   VALUES ('مدرس تجريبي', 'from-sql@edulink.test', crypt('Teacher@12345', gen_salt('bf', 10)), 0, 1, 1);
   ```
2. `curl http://localhost:5279/api/health/db` → لاحظ أن `usersCount` زاد.
3. سجّل الدخول بهذا الحساب ← نجاح الدخول يثبت أن الـ API قرأ الصف من القاعدة الحقيقية.
4. غيّر `access` إلى `0` في Supabase وأعد المحاولة → يجب أن تُرفض بـ **403**.

## التحويل إلى SQL Server (سيرفر الشركة)

### 1) أنشئ القاعدة وشغّل المخطط (ملف واحد يعمل Run)

الملف المُسلَّم **والوحيد**: **`RUN-ON-SQL-SERVER.sql`** في جذر المستودع (نسخ `deploy/sqlserver-setup.sql` و`deploy/EduLink-SQLServer-ascii.sql` حُذِفتا في 2026-10-21 — كان اسمان لملف واحد فيصدّق المشغّل أيهما) — قسم T-SQL من `database/schema.sql` مع ترويسة `CREATE DATABASE` + `USE`. مُهيّأ لـ **SQL Server 2014**: لا `CREATE OR ALTER` ولا `DROP … IF EXISTS` ولا `FOR JSON` ولا تريجرات.

**لا تلصق المخطط يدويًا في SSMS — شغّله بالملف مباشرة:** اللصق اليدوي هو ما أوقع جولة `Msg 156/102/178/111` كاملة، لأن الملصوق كان قسم PostgreSQL من `schema.sql` (993 سطرًا بصيغة `CREATE TABLE IF NOT EXISTS` و`TEXT` و`RETURN NEW`) لا قسم T-SQL:

```bash
sqlcmd -S "SERVER,1433" -U sa -P "PASSWORD" -f 65001 -I -b -i RUN-ON-SQL-SERVER.sql
```

`-f 65001` يقرأ العربية UTF-8، و`-I` يلزم الفهارس المفلترة، و`-b` يوقف الصمت عند الخطأ. الملف تراكمي: تشغيله ثانية يعطي صفر أخطاء.

> **لتوليد الملف بعد أي تغيير مخطط:** عدّل `database/schema.sql` (الملف الوحيد للجداول) ثم استخرج قسم T-SQL بنفس استخراج `deploy/run.sh`، **مع الحفاظ على مقدمة الملف** — فالترويسة وسطرا `CREATE DATABASE` + `USE [EdulinkDb]` يعيشان في `RUN-ON-SQL-SERVER.sql` وحدهما، وكتابة الجسم فوق الملف مباشرة تمسحها بصمت:
> ```bash
> awk '/^-- >>> BEGIN SQL SERVER/{exit} {print}' RUN-ON-SQL-SERVER.sql > .hdr.sql
> { cat .hdr.sql
>   sed -n '/^-- >>> BEGIN SQL SERVER/,/^-- <<< END SQL SERVER/p' database/schema.sql \
>     | grep -v '^/\*$' | grep -v '^\*/$'
> } > RUN-ON-SQL-SERVER.sql && rm -f .hdr.sql
> ```
> **مقيس (2026-10-22):** الأمر يُخرج ملفًا **مطابقًا حرفيًا** للمُسلَّم (`diff -q` صفر، 509 سطرًا في الحالتين) — فلا مقدمة ضائعة ولا سطر زائد.

### 2) ملف الربط: `apps/api/.env`

المنصة تقرأ الربط من ملف **`apps/api/.env`** (مستثنى من Git — السطر 27 في `.gitignore`) يحلّه `Configuration/DotEnv.cs` قبل بناء التطبيق، **ومتغيّرات البيئة الحقيقية أعلى أولوية منه** فلا يُلغي إعدادًا مضروبًا من `deploy/run.sh` أو systemd. القالب الكامل في `apps/api/.env.example`؛ المطلوب منك سطر واحد — كلمة السر:

```ini
ASPNETCORE_ENVIRONMENT=Production
ASPNETCORE_URLS=http://localhost:5279

Database__Provider=SqlServer
ConnectionStrings__SqlServer=Server=nile-server.com,1433;Database=nile-old;User ID=sa;Password=REPLACE_WITH_SA_PASSWORD;Encrypt=True;TrustServerCertificate=True;MultipleActiveResultSets=True

Network__UseForwardedHeaders=true
Network__ForwardedHeadersLimit=1
Meeting__TurnUrls__0=
Meeting__TurnSecret=
Meeting__TurnTtlSeconds=86400
```

- **`ASPNETCORE_URLS` إلزامي هنا:** بدونه لا يربط Kestrel على 5279 فتبدو كل نداءات `curl` فاشلة (`000`) كأن الـ API مات — وهو فخّ مقيس.
- المنفذ بفاصلة `Server=...,1433` (لا نقطتان).
- **التشفير — مقيس من هذا الجهاز على `nile-server.com,1433` (2026-10-18):** بـ **`Encrypt=True;TrustServerCertificate=True`** تمت مصافحة TLS بنجاح ووصل الـ API إلى التحقق من الدخول؛ الفشل الوحيد كان `Error 18456, State:1 — Login failed for user 'sa'` (كلمة السر). **فلا حاجة إلى إطفاء التشفير** مع هذا السيرفر. أما موثّق ما سبق («السائق يرفض المصافحة») فلم أُعِده اليوم ولا أعرف أي تركيبة أخرجته تحديدًا — والتركيبة التي تستخدم `Encrypt=True` **بلا** `TrustServerCertificate` على شهادة غير موثوقة **لم أختبرها**، فلا تُبنى عليها قرارات.
  ⚠️ **ما لا يضمنه هذا:** `TrustServerCertificate=True` = تشفير **بلا تحقّق من هوية السيرفر**، فالمسار محمي من القراءة لا من الانتحال. واللوج يطبع `The negotiated TLS 1.0 is an insecure protocol` — أي أن السيرفر يخدم TLS 1.0؛ الصواب عند التسليم: تفعيل **TLS 1.2** على السيرفر + شهادة موثوقة، ثم `Encrypt=True;TrustServerCertificate=False`. الـ API لا يضيف أيًّا من العلمين تلقائيًا، و`appsettings.json` يبقى بلا سرّ.
- لا يُنشئ الـ API أي جدول: المخطط من `schema.sql` وحده (`EnsureCreated` يعمل على SQLite المحلي فقط).

### 3) شغّل وتحقّق

```bash
cd apps/api && dotnet run -c Release            # يقرأ apps/api/.env تلقائيًا
curl http://localhost:5279/api/health/db
```

`"provider":"SqlServer"` و`"canConnect":true` و`serverVersion` بنسخة SQL Server. **مقيس (2026-10-02)** على قاعدة محليّة باسم `nile-old` أُنشئت من `RUN-ON-SQL-SERVER.sql` وحده: `canConnect:true` ⇒ `POST /api/setup/owner` بـ **200** ⇒ دخول المالك ⇒ `/api/auth/me` و`/api/students` بـ **200**، والقراءة الخلفية تعطي `LEN=11 · DATALENGTH=22 · qmark=0` (عربية الاسم حرفية) وبادئ تجزئة `$2a$11$`.

### فرق سلوكية تخصّ هذا الـ API

| الفرق | السبب |
|---|---|
| `updated_at` يضبطه `EduDbContext.SaveChangesAsync` (لا تريجر) | أي تريجر مُفعَّل يجعل الحفظ يفشل: EF يرسل `INSERT ... OUTPUT INSERTED.id` والمحرّك يرفضه على جدول له تريجر (خطأ 334) |
| أعمدة `token` = `NVARCHAR(200)` | لا فهرس على عمود `MAX`، والتوكن يُبحث عليه بالمساواة في كل طلب (طوله الفعلي 43) |
| حذف حصة مرجعية (تسوية) يدوي | `makeupOfId` مفتاحه `NO ACTION` لأن SQL Server يرفض تعدد مسارات `CASCADE` (خطأ 1785) |

| `GET` | `/api/files/{id}/shared?session=CODE` | مشارك نشط في الغرفة | قراءة الملف **المعروض الآن** في الحصة (`inline` + `Range`) — بلا منح نشط ⇒ **404**، وغير مشارك ⇒ **404**، وبلا `session` ⇒ **400/404** |
| `DELETE` | `/api/files/{id}` | مالك الملف | حذف الصف + الملف من القرص — معرّف غريب ⇒ **404** |
| `WS` | `/hubs/meetings?access_token=…&room=…` | توكن | غرفة الحصة — الدور يُحدَّد من القاعدة، والانضمام يسجّل الحضور. **يُرفض الاتصال بـ `HubException` خارج نافذة الحصة** (`start − Sessions:JoinEarlyMinutes` … `end + Sessions:JoinGraceMinutes`، و`live` تبقى مفتوحة) فمعرفة كود الغرفة لا تفتحها |
| `GET` | `/api/health/db` | عام | حالة الاتصال بالقاعدة |

### المصادقة

توكن عشوائي 256-bit يمثّل **جلسة جهاز واحد** ويُخزَّن في `Edu_Tokens` (kind = staff/student/parent)، ويُرسل في كل طلب:

```
Authorization: Bearer <token>
```

- **الدخول من أكثر من جهاز مسموح** (حد 10 جلسات للحساب؛ الأقدم يُلغى تلقائيًا). تسجيل الخروج يُلغي جلسة الجهاز الحالي فقط.
- عمود `token` في جداول الحسابات = آخر توكن منشأ (عرض/توافق فقط؛ الصلاحية تُقرأ من `Edu_Tokens`).
- الحساب الذي `access = 0` **لا يستطيع الدخول إطلاقًا** (يرجّع `403`).
- كلمات المرور تُجزَّأ بـ **bcrypt** في التطبيق — لا يُخزَّن نص صريح في القاعدة أبدًا.

|---|---|
| 0 | مدرس |
| 1 | مشرف |
| 2 | مدير |
| 3 | أونر |

القيمة الأعلى = صلاحية أوسع. الطالب `role = -1` وولي الأمر `role = -2` مع claim `edu:aud` (staff/student/parent).

**مصفوفة الصلاحيات (قرار صاحب المشروع — الخطوة 26):** القرار يُتَّخذ هنا في الخادم، والواجهة تُخفي الأزرار وفق نفس الحارس (`lib/roles.ts`) ولا يُعتمد على الإخفاء وحده.

| الدور | حصص | حسابات | إحصائيات |
|---|---|---|---|
| **مدرس (0)** | ينفّذ حصصه فقط: دخول الغرفة، إنهاء، حضور. **لا** إنشاء/إلغاء/تأجيل | لا شيء | `GET /api/sessions/stats` لنفسه |

### حسابات ومواد

- **`states`** في `Edu_Users`/`Edu_Students`/`Edu_Parents`: 0 = غير ظاهر، 1 = ظاهر. أي حساب يُنشأ من الواجهة يُخزَّن بـ `states=1` (ما تُنشئه الإدارة ظاهر بطبيعته)، والتسجيل يُتحقق من `access=1` فقط.
- **`subject`** في `Edu_Sessions` نص حر بطبيعته (VARCHAR) — لا توجد قائمة مواد مغلقة، لأن المنصة تُباع لمؤسسات بقوائم مختلفة. الواجهة تعرض الاسم الحرفي لأي مادة خارج المواد الخمس المعروفة.

## نقاط مفتوحة في الباك اند

1. **لا مدة صلاحية للتوكن** — الجلسة تُلغى بالخروج أو عند تجاوز حد الأجهزة؛ لا تجديد تلقائي. (موثّق في `docs/11` قائمة ما قبل التسليم)
2. ~~جلسة واحدة لكل مستخدم~~ — **مُطبَّق**: `Edu_Tokens` يجلس لكل جهاز (حد 10، الأقدم يُلغى) للموظف والطالب وولي الأمر.
3. **الدخول برقم الهاتف** غير مدعوم في الخادم بعد (البريد فقط).
4. **Google Sign-In** غير مدعوم بعد.
5. ~~لا يوجد Rate limiting~~ — **مُطبَّق بثلاث حصص من `RateLimit:*`**: الدخول `LoginPermitPerMinute=120` لكل IP، وباقي `/api` `ApiPermitPerMinute=600` لكل جلسة (والمجهول بالـ IP)، واتصالات الغرف `/hubs` `HubPermitPerMinute=3000` **لكل جهاز** (مفتاحه `access_token`)، **وقفل لكل حساب** بعد `LoginFailuresPerAccount=8` محاولات داخل `LoginLockoutMinutes=5` (`LoginAttemptTracker`، يرفض `429 + Retry-After` حتى بالكلمة الصحيحة أثناء القفل). **خلف nginx يجب** `Network:UseForwardedHeaders=true` مع تحديد الوسيط، وإلا تُحسب المؤسسة كلها IPًا واحدًا — التفاصيل والقياس في `docs/11` §6. **والحارس الفعلي ضد التزوير هو `Network:ForwardedHeadersLimit`** (= عدد الوسائط المأمونة: 1 لخطة `deploy/nginx.conf`، 2 فقط خلف CDN): به تُقرأ القيمة التي أضافها الوسيط وحدها، فيبقى تزوير `X-Forwarded-For` بلا أثر — `python tools/verify-xff-spoof.py green` يقيس ذلك (حدّ 1 ⇒ 429 عند المحاولة 121 رغم ترويسة مزوَّرة مختلفة كل مرة؛ حدّ 4 ⇒ صفر 429 أي الحدّ متجاوَز).
6. ~~الطلاب وأولياء الأمر بلا نقاط نهاية~~ — **مُطبَّق**: دخول/عزل/حضور للطلاب، ودخول/أبناء/ربط لأولياء الأمور، ورسائل وإشعارات للأدوار الثلاثة (`docs/11` §6).
7. **إعداد الخطة الباردة (`GET /api/meeting/ice`، يتطلب توكنًا):** يعيد `iceServers`؛ ومع `Meeting:TurnSecret` يوقّع لكل مستخدم `username = "<unix expiry>:<userId>"` (القيمة **مطلقة** لا مدة) و`credential = base64(HMAC-SHA1(secret, username))` — نفس ما يفحصه coturn بوضع `use-auth-secret`. لا أسرار ثابتة في المتصفح، والتوكن ينتهي بعد `Meeting:TurnTtlSeconds` (افتراضي 86400). **مقيس بـ** `python tools/verify-ice-turn.py green` (إعادة حساب مستقلة للتوقيع + صيغة username + العمر = TTL + `401` بلا توكن) و`red` لإثبات أن الفحص يرفض عند اختلاف السرّ؛ و`deploy/run.sh` يشغّلها ويقاطع `Meeting__TurnSecret` مع `static-auth-secret` في `deploy/turnserver.conf`. إن تعذّرت قراءة الإعداد لا تسقط الواجهة بصمت: تعرض تنبيهًا أن الغرفة تعمل بـ STUN العام فقط.
8. **عقد الانضمام في الغرفة (`join`):** الوسيط `participantRole` الذي يرسله المتصفح **لا يُقرأ للترخيص إطلاقًا** — الخادم يحسب الدور من القاعدة (طالب الحصة = `student`، ولي الأمر المرتبط = `observer`، مدرّس الحصة = `teacher`، وكل من `supervisor` فأعلى = `observer`، وغير هؤلاء `HubException`). و`RoomInfo` المُرجعة **تحتوي الآخرين فقط** (لا نفس المشارك)، فالدور المحسوب لا يُقرأ من نتيجة `join` بل يصل بقية الغرفة من رسالة `peer-joined` التي يكتبها الخادم بنفسه؛ وكل تطبيق داخلي (إنهاء الحصة، الحالة، الحضور) يستخدم الدور المحسوب المخزَّن على الاتصال. `tools/hub-through-proxy-check.mjs` يقيس الاتجاهين: مطالعة `'teacher'` من مالك ⇒ `'observer'`، ومطالبة `'student'` من مدرّس الحصة ⇒ `'teacher'`. **وبالإضافة إلى الدور، النافذة تُفرض داخل الـ Hub نفسه** (`SessionWindow.Evaluate` بساعة **الخادم**) قبل أي تسجيل: خارجها `HubException` برسول يفهمه المستخدم (لم يحن موعدها / انتهت دورتها) — فالغرفة لا تُفتح بمعرفة كودها ولا بساعة جهاز. **والوقت الفعلي يُقاس لا يُبلَّغ:** كل اتصال يفتح شريطًا في `Edu_SessionPresence` (`accountKind/accountId/roomRole/joinedAt`) ويختمه عند `OnDisconnectedAsync` بـ `leftAt/durationMs`، فمجموع أشرطة الحساب = دقائقه هو (**الخروج المؤقت ثم العودة يُحسبان معًا**، لا يُمحى الأول كما كان يحدث مع `attendance.LeftAt = null`)، ومجموع كل الأشرطة = `actualMinutes` للحصة. البوابة: `python tools/verify-session-window-and-hours.py` (27 بندًا، وجهان مقيسان).
9. **إبطال الجلسات عند تغيير كلمة السر — غير مطبَّق (مقيس 2026-10-01):** `PATCH /api/users/{id}` (ومسارا الطالب وولي الأمر) يستبدل تجزئة كلمة السر وحدها، وصفوف `Edu_Tokens` لذلك الحساب تبقى كما هي، والتوكن لا ينتهي بالزمن ⇒ **جهاز مسجَّل دخولًا قبل التغيير يبقى يعمل** حتى الخروج أو بلوغ حدّ 10 أجهزة. عند التسليم: دوِّر كلمات السر ثم `DELETE FROM dbo.[Edu_Tokens];` (أو بـ `userId`) واختبر دخولًا حقيقيًا من كل جهاز. جعل ذلك أوتوماتيكيًا قرار مؤجَّل من صاحب المشروع. **والخطوة البديلة مُثبتة:** بعد `DELETE FROM dbo.[Edu_Tokens];` رجع التوكن القديم **401** على `/api/auth/me` (كان 200 قبله). و`tools/verify-default-credentials.py` بوابة آلية تقيس البند: تخرج 1 إن قبل النظام أي كلمة افتراضية موثّقة (كشفت 24 حسابًا على قاعدة مزروعة)، و0 بعد التدوير — موصولة في خطوة الحالة بـ`deploy/run.sh`.
10. **البريد/Push للإشعارات** غير مُنفَّذ — `Edu_Notifications` داخلي فقط.
11. **بصمات بيانات التطوير تُقاس قبل التسليم (`tools/verify-no-dev-data.py`):** لا تعتمد على عدد صفوف، بل تقرأ بريد الزرع من `apps/api/seed_dev.py` (وتُوسّع سلسلة `seed.student{i:02d}@…` المُولَّدة من نص المصدر) ثم تعدّ `/api/users|students|parents` وتخرج **1** على أي حساب مزروع أو أي بريد `@edulink.test` عدا بريد من شغّل الفحص. **مقيس (2026-10-01):** على قاعدة LocalDB مزروعة (`users=8 · students=12 · parents=4 · sessions=80 · notifications=403`) كشفت **23 بصمة** وخرجت 1؛ وبعد الحذف بالترتيب الذي أُقرأ من `sys.foreign_keys` (لا ترتيبًا مُخمَّنًا — `Edu_Sessions` مقيدة بـ `Edu_Users` و`Edu_Students`، و`Edu_Relations` بـ `Edu_Students` و`Edu_Parents`، بينما `Edu_Notifications`/`Edu_Tokens` بلا قيود فتُحذف للوقاية من اليتيم) صارت `users=1` والبقية صفرًا فخرجت **0**. تعذّر الدخول (`401`) أو أصل غير reachable أو شكل استجابة مجهول ⇒ **خروج 1**، فلا يُحسب «لم أُتحقق» نجاحًا. موصولة في خطوة الحالة بـ`deploy/run.sh`، والإجراء الكامل في `docs/11` §7.
12. **حالة الغرفة المشتركة (الخطوة 62، ونموذجها المُصنَّف في الخطوة 64) — في ذاكرة
    الخادم لا في القاعدة:** `join` يرجع `RoomInfo(Room, Self, Me, Peers[],
    Board{ IsOn, Stage, Annotations[], Doc })` — و`Self` هو `Context.ConnectionId` لأن
    عميل SignalR في المتصفح لا يستطيع قراءة معرّف اتصاله، و`Me` صف المنضم نفسه **بما قرره
    الخادم من صلاحياته**: رسالة `perms` وحدها قد تصل قبل أن يخزّن العميل معرّف اتصاله، فلا
    يعرف أنه ممنوع.
    لكل غرفة `RoomState`: كائنات الشرح FIFO بسقف **300 كائن و48KB** (الأقدم يسقط أولًا — بلا
    سقف كانت الحصة الطويلة تُنمّي ذاكرة الخادم بلا حدّ)، و`stage` (`video|board|doc`)
    و`boardOn` و`doc` المعروض. **مفروض في الخادم بـ `IsHost()`** (مدرس الحصة أو `supervisor`
    فأعلى — من القاعدة لا من مطالعة المتصفح): `setStage` و`shareDocument` و`clearWhiteboard`
    و`endRoom`. كانت `endRoom` تقبل أي `observer` فيقدر **ولي أمر مراقب** أن يُنهي حصة مدرّس
    ابنه، وكانت `sendChat` تُرسل للمجموعة فترجع للكاتب **مرتين** — صارا `OthersInGroup`
    و`IsHost()`. **و`clearWhiteboard` للمجموعة كلها** بمن فيهم من ضغط الزر (كان
    `OthersInGroup` فيمسح شاشة الطالب وتبقى شاشة المدرس مكتنزة بما مسحته).
    **الشرح كائن مُصنَّف لا مقطع خطّي:** `annotate(batchJson)` تستقبل دفعة عمليات
    `[{op:'add',a},{op:'del',ids}]` حيث `a = {id, tool, color, width, points[], text?}`
    و`tool` من `pen|highlighter|line|arrow|rect|ellipse|text` (الممحاة **حذف بمعرّف** لا
    أداة محفوظة، فتلك زووم: لمسة تُمسح الكائن كله). العميل يدمج ما يُثبَّته في رسالة واحدة
    كل ~50مللي ثانية (سقف **64 عملية** للدفعة و**30 دفعة/ثانية** للاتصال، والزيادة
    `HubException` بسببها المسمّى). الخادم يفحص كل حقل قبل أن يخزّن أو يبثّ: الأداة معروفة،
    `id` ≤ 64، لون `#rgb|#rrggbb`، سماكة `1..40`، عدد نقاط الشكل **أربعة بالضبط** والنص
    **واحدة**، والقيم كلها داخل `0..1` — **وأسقط التالف وحده** فلا تُطير ضربة واحدة بقية
    الغرفة، ولا يُقبل نصّ أطول من 200 حرف فلا يترسّط HTML في `fillText`.
    **التراجع على مستوى الكاتب:** `undoAnnotation()` يمشي المخزن من آخره بحثًا عن آخر كائن
    **كتبه هذا الحساب** (بمعرّف الحساب لا بالمقبس) ويعيد معرّفه ليُطبَّقه كاتبه فورًا، ويُبلَّث
    به البقية عبر `del` — فلا يمسح المدرس تراجعًا كائنَ الطالب.
    **المؤشر الحيّ:** `sendPointer(x, y, tool)` يُمرَّر ولا يُخزَّن (سقف 20/ثانية لكل اتصال،
    والتجاوز **يُسقط بصمت** لأن تأخّر اليد أهون من إغلاق غرفة)، فيرى الطرف الآخر يد صاحبه
    باسمها ولا يرى صاحبها شيئًا، وتختفي عند سكوته.
    **الصلاحيات قرار مدرّس لا قرار متصفح:** `setPermissions(targetConnId, canSpeak, canVideo,
    canWrite, canShare)` للمضيف فقط، وتُكتب في `RoomState.Blocks` على **معرّف الحساب** لا على
    المقبس — فاتصال ثانٍ لنفس الطالب أو عودة بعد انقطاع يولدان ممنوعين (كان التوريث من
    الاتصالات الحيّة فيسقط القرار مع أول انقطاع، وتبقى شاشة المدرس تعرض الزر مقلوبًا).
    المدرس **يحصر ولا يرفع**: طلب «اسمح بالمشاركة» لطالب سقف دوره لا يشارك يبقى محصورًا
    (`RoomState.Defaults` يحفظ سقف الدور لكل حساب). والطالب لا يرفع منعًا عن نفسه:
    `setState(muted=false)` منه وهو ممنوع يبقى `muted=true` في عين الغرفة. النداء على معرّف
    خرج يرفض بـ «هذا المشارك لم يعد في الغرفة» — كان يرجع **صامتًا** فتكذب الشاشة.
    **منح الملف:** `shareDocument` يقبل **ملف المرسل نفسه** في `Edu_Files` (غيره ⇒
    `HubException`) ويفتح منحة قراءة في `RoomSharedDocs` تُغلق عند تبديل الملف أو إغلاقه
    أو مغادرة آخر مشارك أو إنهاء الحصة؛ و`GET /api/files/{id}/shared?session=` يقيّم
    المشاركة النشطة في الخادم (`MayAttend`) فيعيد **404** للغريب أو لملف غير معروض.

    **وما لم يُقنع بالبقاء:** جُرِّب قفل غرفة (`SemaphoreSlim`) ليُطبَّق ترتيب السلك مع
    ترتيب المخزن، فقِيس: عشرون زوجًا `annotate` ثم `clearWhiteboard` **بلا انتظار** من نفس
    الاتصال وصلت كلها بالترتيب ولقطة المتأخر فضياء — SignalR يحافظ على ترتيب نداءات اتصال
    واحد، فالقفل أُرجع ولم يُترك كودًا بلا غرض.
13. **بوابة الشاشة نفسها (`node tools/verify-classroom-controls.mjs`):** عيوب الوسائط التي
    بلغ عنها صاحب المشروع كلها تُرى على الشاشة لا في عقد الخادم، فالبوابة تفتح كروم حقيقيًا
    بـ `--use-fake-device-for-media-stream` على بناء مُقدَّم عبر `tools/edge-proxy.mjs`،
    وتدخل تبويبين (مدرس + طالب) من `/sessions/{id}/live` كما يفعل المستخدم، وتنقر بأحداث
    فأر حقيقية (بلا user activation يرفض المتصفح ملء الشاشة فيصير الأحمر كذبًا). القياس من
    داخل الصفحة بوسطاء لا يغيرون سلوكها: `RTCPeerConnection` مُغلَّف للتسجيل، والتقاط
    إطارات WebSocket (لتفريق «الخادم لم يرسل» عن «أُرسل والشاشة لم تتصرّف»)، و`getUserMedia`
    مُسجَّل (للتفريق بين لم يُطلب فيديو وطلب ثم مات)، وحصرة البكسل المرسوم على كل لوحات
    القلم بـ `getImageData`. تكتب حسابات وحصصًا بنطاق `@tila.test` ⇒ قاعدة اختبار ثم
    `deploy/cleanup-verification-data.sql`.
    **البنود العشرة:** وسائط مستقبَلة في الاتجاهين (لا «متصل» بلا بايتات)، سقف `maxBitrate`
    و`contentHint` و`frameRate` على الـ sender نفسه، قلم المدرس يصل الطالب بصفحة رسالات
    واحدة، مسح المدرس يُبيضّ شاشته هو، منع المدرس للقلم (رسمته تتوقف **والخادم يرفض ضربته
    الحرفية** بردّ `type:3` فيه السبب العربي دون أن يقذفه من الغرفة)، رفع المنع يعيد القلم،
    الإسكات يُطفئ مسار الطالب نفسه، قلب الكاميرا لا يقتل المسار الحيّ، ملء الشاشة يمسك
    البلاطة، والكتابة الكثيفة تصل كاملة. ثم سبعة لنموذج الشرح المُصنَّف: **الأشكال كائنٌ واحد
    بأداته** (`rect`/`ellipse` يصلان كما رُسمًا و`data-tool` يقرّر الأداة على السطح نفسه)،
    **لون الكاتب وسماكته داخل الكائن نفسه** (رسالة واحدة تحملهما معًا، لا لون في رسالة
    وسماكة في أخرى)، **الممحاة تُمسح الكائن كله من الشاشتين وتترك ما حوله** (6862 → 0
    والمستطيل المجاور باقٍ — فالمحاة كائنية لا مسح عام)، **تراجع المدرس يمسح آخر كائن له
    وحده** (كائن الطالب يبقى في الطرفين)، **النصّ يصل حرفيًا** (`caret` على اللوحة ← كتابة
    ← Enter ← «مرحبا» عند الطالب وتحرّر اللوح من الحقل)، **يد المشارك باسمها عند الطرف الآخر
    وحدها** وتختفي عند السكون ولا تلتقط حدثًا (العنصر تحت مركزها هو اللوحة)، و**المسح يتجاوز
    أي دفعة شرح لم تُرسَل بعد** فلا يستعيد الطالب حبرًا مسحه مدرّسه. **ثم سبعة على مقاس جوال
    حقيقي (390×844 بلمسة مفعّلة، والصفحة تُحمَّل عند المقاس لا تُعاد تحجيم وهي قائمة):**
    الفيديو البعيد يملأ 94% من المسرح وصورة المدرس **شريحة ركن 105×59 واللمسة عند مركزها
    تصل صورتها فعلًا** (`elementFromPoint` + أقرب `figure[data-self]`) بلا تمرير صفحة وبلا
    سبورة مرئية؛ **صفر زرّ ملء شاشة مرسوم** من أصل اثنين في الشجرة (الملء تخطيط لا استجابة
    متصفح، فبالون «رفض المتصفح ملء الشاشة» لم يعد له ما يُنتجه)؛ زرّ **«ملف للحصة» داخل
    `footer`** بمقاس 44px يفتح المنتقي بزرّ «رفع من الجهاز» ثم يُغلق؛ **السبورة تملأ 74% من
    المسرح بشريحتي فيديو جنبًا إلى جنب، وسحبة قلم على الجوال تصل شاشة الطالب (2332 بكسل) ثم
    يمسح نظّف الطرفين**؛ ثماني أدوات كلها داخل الشاشة في شريط أفقي واحد بارتفاع 42px؛ شارة
    الأداة الجارية تتبدّل بالنقر؛ وعلى الحاسوب ثماني رسومات متمايزة 22px داخل أزرار 70×40
    بأسمائها (قلم، **مظلل**، خط، سهم، مستطيل، دائرة، نص، ممحاة — والبوابة تطبع الأسماء كما
    تقرأها الشاشة، فهي أمسكت تسمية «ناسر» الخاطئة على الشاشة وصحّتها إلى «مظلل»).
    **أخضر 24/خروج 0** (مقيس 2026-11-07)، والحالات الحمراء المقيسة — كلٌّ أحمر وحده لا غير:
    حذف سطر `if (!peer.CanWrite) throw` من فرع الشرح ⇒ بند المنع (البكسل 0 → 694 والردّ
    `result:null`)؛ `hitAnnotation` تُرجع false ⇒ بند الممحاة؛ حذف `event.preventDefault()`
    من فرع النص ⇒ بند النصّ (الـ caret يُولد ويُغلقه `onBlur` قبل أن يُكتب حرف — عيب حقيقي
    كَشفته الجولة الأولى ولم يكن في الحسبان)؛ **ورجوع `clearBoard` إلى ما قبل إسقاط الطابور
    ⇒ بند المسح الفوري، وهو يقيس ترتيب السلك: «أُرسلت 1 دفعة بعد قرار المسح (آخر add في
    إطار #16، والمسح في #15) — الطالب 227 بكسل والمدرس 0»**؛ وإلغاء فلتر الكاتب أو بثّ
    المؤشر في الخادم ⇒ بنداه في البوابتين. **ولبنود الموبايل والرسومات ثمانية أحمر واحد
    واحد:** كسر مُعرِّف شريحة النفس ⇒ «صورتك ليست شريحة صغيرة: 374×716»؛ حذف `display: none`
    عن زرّ ملء الشاشة ⇒ بند اللمس (زرّان
    ظاهران @53,68)؛ تغيير `data-share-file` ⇒ بند الشريط السفلي؛ تثبيت ارتفاع اللوح على
    210px ⇒ 22% من المسرح؛ تصغير أزرار الأدوات إلى 30px ⇒ بند الإصبع؛ نسيان قاعدة `.toolNow`
    عند العرض الضيق ⇒ بند الشارة؛ تصغير الرسمة إلى 15px ⇒ بند الحاسوب؛ وجعل المستطيل يرسم
    رسمة الخط ⇒ بند الحاسوب أيضًا.
    **وفخاخ سبعة في الأداة نفسها كُشِفت بالتشغيل لا بالقراءة:** غلاف `WebSocket` لا بدّ أن ينسخ
    ثوابته الساكنة (`OPEN/CLOSED/…`)، وبلا النسخ قررت صفحة SignalR أن المقبس «ليس OPEN»
    ففشلت البنود كلها وكأن المنتج مكسور؛ وإطار النداء الخام لا يحمل `protocol/version`
    (هما للمصافحة وحدها) وإلا أغلق الخادم الاتصال بردّ عام بلا السبب. و`check-injection` صريح
    قبل أي بند: إن لم يعمل سكربت القياس تقول الأداة ذلك باسمها. وثالث أن `annotate` يستلم
    الدفعة **نصًّا** فإطار SignalR يحمل الاقتباسات مُفرَّغة ويُلغي غير ASCII إلى
    ‎\uXXXX‎، فوجاف «أداة» أو «نص عربي» بشكله الحرفي لا يطابق رسالة سليمة ⇒ تُقرأ
    الإطارات بعد تفكيك التفريغ (`__wsNorm`) لا قبله؛ ورابع أن الدفعة تتأخر ~50ms، **والانتظار
    حتى وصولها وحده لم يكفِ**: كان البند ينقر «مسح» بعد بحث نصي عن الزرّ (نداءات عدة + 250ms
    نوم داخل النقرة) فخرجت الدفعة **قبل** القرار في كل جولة، وحُمِّل المنتج ذنب الأداة (أحمر
    جولة 2026-11-07: «أُرسلت 1 دفعة شرح» والطالب 0 بكسل). صار الحكم من **ترتيب الإطارات على
    السلك** (`__seq`/`__addSeq`/`__clearSeq` في غلاف المقبس)، ويُتحقَّق من موضع الزرّ بنقرة
    مؤكَّدة واحدة على وسام `data-board-clear` قبل السباق، ثم press+release بلا حركة ولا نوم،
    وتُعاد المحاولة خمسًا، وإن فشلت سمّت الأداة نفسها لا المنتج، **وبضبط داخل البند نفسه**:
    سحبة بلا مسح يجب أن تُخرج دفعة، وإلا كان «لم تخرج دفعة» نجاحًا بلا مقابل؛ وخامس أن تبويبين في نفس كروم يتقاسمان
    **localStorage واحدًا**، فأية إعادة تحميل تُدخل شاشة المدرس **بتوكن الطالب** (قيس: الشريط
    السفلي فقد أزرار المضيف والبلاطة كُتبت «طالب») — صار التبويب يحمل توكنه ويعيد كتابته قبل
    التحميل ويتأكد أن اسم المدرس على شاشته؛ وسادس أن `DOMRect` فيه `width/height` لا `w/h`،
    ففحص «هل من طبقة فوق المسرح؟» كان يقارن `NaN` ويُجيب «لا طبقة» بينما لوحة المحادثة تغطي
    كل شيء — **أخضر كاذب** أمسكته ملامسة العنصر العلوي وحدها (`elementFromPoint`)؛ وسابع أن
    النقر بإحداثيات الزرّ لا يثبت أن اللمسة وصلت ذلك الزرّ، فالبند كان يقيس «لمسة على زرّ
    المستطيل» بينما اللوحة تلتقطها — صار `clickSel` يقرأ آخر لمسة وصلت الصفحة ويطلب اسم الزرّ
    نفسه (ولأن «السبورة» كلمة داخل «تكبير السبورة» فالبحث النصّي وحده يضغط زرًا آخر).
